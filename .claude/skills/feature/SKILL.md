# Feature Development Workflow

`$ARGUMENTS` に記述された新機能開発を完遂してください。

## 進め方

以下のフェーズを順番に実行してください。各フェーズ完了後に進捗を報告してください。

### Phase 1: 要件定義
以下を実施:
- `$ARGUMENTS` の機能を分析してユーザーストーリーと受け入れ条件を作成する
- 既存コードを確認してスコープと技術的考慮事項を整理する

### Phase 2: 設計
以下を実施:
- アーキテクチャ設計方針を作成する
- コンポーネント構成と実装指針を提供する
- API 契約（エンドポイント・型定義）を定義する

### Phase 3: 実装
設計に基づきバックエンドの実装を行う。

### Phase 3.5: リファクタリングチェック（必須）

**このフェーズは省略不可。** 実装完了後、品質保証の前に必ず実施する。

#### Step 1: 実装コードの品質チェック

以下のルールに違反していないか確認する:

1. **ファイルサイズ**: 新規・変更ファイルが300行を超えていないか
   ```bash
   git diff --name-only HEAD~1 | xargs wc -l | sort -rn | head -10
   ```

2. **後方互換**: 既存の import パスを壊していないか

3. **Docstring 規約準拠**: 新規・変更した公開 API に docstring があるか
   - Python: Google Style（サマリー + Args + Returns + Raises）

#### Step 2: 違反があれば修正

違反が見つかった場合、修正してから Phase 4 に進む。

### Phase 4: 品質保証
以下を実施:
- コードレビュー（品質・規約準拠・セキュリティ）
- pytest テスト実行:
  ```bash
  uv run pytest
  ```
- リント実行:
  ```bash
  uv run flake8
  ```

品質ゲート:
- Critical 所見がある場合 → 実装を修正してから再レビュー
- テスト失敗がある場合 → 修正を実施
- 全て OK の場合のみ次のフェーズへ

### Phase 5: バージョン管理
以下を実施:
- `feature/<機能名>` ブランチを作成
- 変更をコミット（Conventional Commits: `feat(scope): [説明]`）
- PR を作成（レビュー所見をPR本文に含める）

## 完了報告

全フェーズ完了後、以下をユーザーに報告する:
1. 実装した機能のサマリ
2. 作成したファイル一覧
3. テスト結果
4. セキュリティレポートの概要
5. PR URL
