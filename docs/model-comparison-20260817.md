## 3. 事実忠実性の検証（入力原文との照合）

`consistency` ノードが gpt-oss の出力に付けた `review_flags` 3件を、入力原文と照合した。
**3件とも実際に入力へ根拠が無く、フラグは正しい。**

### 3.1 指導内容の水増し（gpt-oss）

入力原文（20230212 カルテ#2、全文）:

```
患者への退院後生活指導実施
家族（長女）に介護方法の指導を実施
転倒予防のための環境整備について説明
```

gpt-oss の生成:

> 退院後の生活指導として、**術後のリハビリ計画、歩行補助具の使用方法、創部管理**について説明し、
> 長女に介護方法（**体位変換**、転倒予防のための環境整備）を指導した。

太字の4項目は入力に存在しない。「介護方法」という語から具体的な指導項目を作り出している。

gemma4 の生成:

> 患者に対し退院後の生活指導を実施。また、家族（長女）に対し介護方法の指導および、
> 転倒予防のための環境整備について説明を行った。

入力の3行に対応し、追加が無い。

### 3.2 同意の記載（gpt-oss）

入力原文（20230220、全文）:

```
退院前カンファレンス
退院予定日: 2023年2月22日
退院先: 自宅（長女と同居）
継続問題: 転倒リスク、糖尿病管理、疼痛管理
退院後フォロー: 整形外科外来 2週間後、訪問リハビリ週2回
処方: ロキソプロフェン 60mg 頓服、アムロジピン 5mg 1日1回、メトホルミン 500mg 1日2回
ケアマネージャーと連携済み
```

gpt-oss の生成:

> 退院前カンファレンスにて、退院後のフォローアップ…について説明し、**患者・家族は理解し同意した**。

カンファレンスの決定事項は記載されているが、患者・家族への説明とその受容は記録されていない。
「理解し同意した」は入力に無い。カルテ記載としては、患者の反応を記録なしに書くことになる。

gemma4 は同じ内容を `others` に「退院前カンファレンス実施」「ケアマネージャーと連携済み」等の
事実列挙として書き、説明・同意には言及していない。

### 3.3 略語展開の不安定性（gpt-oss）

入力は `ドレーン: JP ドレーン 1本留置` と略語のみを記載している。

同一入力・同一設定（temperature 0.1）で2回実行した gpt-oss の出力:

| 実行 | 生成された展開 | 正誤 |
|---|---|---|
| 10:14 | 「JP（**ジャパニーズ・パロナル**）ドレーン」 | 誤り（実在しない語） |
| 21:12 | 「JPドレーン（**Jackson-Pratt** ドレーン）」 | 正しい |

JP ドレーンは Jackson-Pratt ドレーンであり、10:14 の実行は臨床用語の捏造にあたる。
temperature 0.1 でも実行ごとにブレる。

gemma4 は `JPドレーン1本留置` と入力どおりに記述し、展開しなかった。

なお 10:14 の実行では gpt-oss は疼痛管理を「セフトリアキソン静注とロキソプロフェン経口投与」と
記述したが、入力（`術後の疼痛管理: NRS 5/10 → フェンタニル持続投与開始後 NRS 2/10 に改善`）と
一致しない。21:12 の実行では「フェンタニル持続投与」と正しく記述している。
gemma4 は 1 回の実行で正しく「フェンタニル持続投与」と記述した。

## 4. 各モデルの特性

### gpt-oss:120b

- 記述量が多く、情報を文章として統合する。`risks` では継続問題3点に薬剤名
  （メトホルミン 500mg、ロキソプロフェン 60mg 頓服）と背景（術後下肢筋力低下）を補って構成する。
  補った情報自体は入力の別行に存在するため、統合としては妥当。
- 一方で、入力に無い内容を補完する傾向があり（3.1 / 3.2）、それが `review_flags` として顕在化する。
- 略語展開・薬剤名の記述が実行ごとにブレる（3.3）。
- 所要時間は gemma4 の約4倍。

### gemma4

- 入力に忠実で、未支持 claim を生成しなかった（`review_flags` 0件）。
- 数値の転記精度が高い。手術時間 2時間15分、出血量 350mL、各日のバイタルを漏らさず記載する。
  略語には正しい原語を併記する（MMT: Manual Muscle Testing、NRS: Numerical Rating Scale）。
  これらは入力に根拠があるか一般的に定まっている語であり、3.3 のような捏造には至っていない。
- `risks` は入力の `継続問題: 転倒リスク、糖尿病管理、疼痛管理` を箇条書きにするに留まり（53字）、
  薬剤や背景の統合はしない。臨床的な読み物としては薄い。
- `nursing_process` に 20230220 の記録を含めず `others` に置いた。経過としての時系列は 20230215 で終わる。
- 所要時間は 22.0s。

## 5. 所見

- **看護サマリー生成というタスクでは、gemma4 の未支持 claim 0件は重い利点**である。
  gpt-oss の3件はいずれも「もっともらしいが記録に無い」記述で、`review_flags` が
  無ければ人手で検出しにくい。特に「患者・家族は理解し同意した」は、記録に無い患者反応を
  カルテに書くことになる。
- **ただし gemma4 は記述が薄い**。`instruction` 75字 / `risks` 53字は gpt-oss の
  206字 / 161字に対して情報統合が不足している。運用でどこまでの記述量を求めるかで評価が変わる。
- **`review_flags` の機構は有効に働いた**。gpt-oss の3件は全て真陽性で、
  誤検出（入力に根拠があるのにフラグが立つケース）は無かった。
- 速度差（22.0s vs 88.8s）は大きいが、いずれも実用範囲内。

### 次に検証すべき点

- 本比較は 1 患者・1 サンプル（約60行）での結果である。実データの長い記録
  （`SINGLE_PASS_TOKEN_THRESHOLD` を超え section-routed map に分岐するケース）では
  補完検索ループが動くため、傾向が変わる可能性がある。
- gemma4 の記述量不足がプロンプト調整で改善するか。
- gpt-oss のハルシネーションが temperature 以外の要因（プロンプトの指示強度）で抑制できるか。
